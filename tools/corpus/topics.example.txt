# tools/corpus/generate.sh に渡すお題の例。1 行に「slug: お題」。
# 空行と # で始まる行は読み飛ばす。slug は出力のファイル名 (<slug>.md) になる。
#
# 実際の校正では、集めた人の文書 1 件ごとにお題を 1 行書き、slug を人の文書の
# ファイル名 (拡張子を除く) と同じにする。同じ相対パスの文書は、noslop calibrate で
# 人と生成が同じ側 (校正用か検証用) に入る (docs/calibration.md)。

commute-reading: 通勤電車の 20 分で本を読む習慣を半年続けて、変わったことと続けるための工夫
home-network: 自宅のネットワークを見直して、在宅勤務中のビデオ会議が途切れなくなるまでの手順
meeting-minutes: 会議の議事録を当日中に共有するために、書き方の型を決めたときの話
first-marathon: 初めてのフルマラソンに向けた半年間の練習と、本番で失敗したこと
balcony-garden: ベランダで育てやすい野菜と、夏場の水やりで気をつけること
review-comments: コードレビューの指摘を相手に伝わりやすく書くために心がけていること
team-backup: 5 人のチームで、データのバックアップの方針を決めたときに話し合ったこと
onboarding-week: 新しく入った人が最初の 1 週間で困らないように、受け入れ側で準備すること
home-coffee: 家で淹れるコーヒーの味を安定させるために、道具と手順で変えたこと
budget-midyear: 部署の年間予算の使い方を半期で見直した結果と、下期に向けた方針
library-visit: 地域の図書館を久しぶりに使って気づいた、この 10 年での変化
incident-review: 深夜に起きたサービス障害の振り返りと、再発を防ぐために決めたこと
moving-checklist: 引っ越しの 1 か月前から当日までにやることを、実際の失敗をもとに整理する
test-flakiness: ときどき失敗する自動テストを調べて、原因ごとに直していった記録
cooking-batch: 週末にまとめて作り置きをするときの献立の決め方と保存の注意
survey-results: 社内アンケートの結果から見えた、働き方についての要望と今後の対応
old-camera: 祖父の古いフィルムカメラを修理に出して、もう一度使えるようにした話
api-versioning: 公開している API の互換性を保ちながら、仕様を変えていくための決まりごと
cycling-commute: 自転車通勤を始めるまでに迷ったことと、雨の日の工夫
vendor-selection: 業務システムの委託先を選ぶときに、比べた観点と決めた理由
sleep-habits: 寝る前のスマートフォンをやめて、朝の過ごし方がどう変わったか
log-retention: ログの保存期間と保存先を見直して、費用と調査のしやすさを両立させた方法
local-festival: 地元の夏祭りの運営を手伝って知った、準備の大変さと楽しさ
handover-notes: 異動の前に、担当業務の引き継ぎ資料をまとめるときに気をつけたこと
reading-group: 社内で技術書の読書会を始めて、1 年続けてわかったこと
winter-hiking: 冬の低山を歩くときの装備と、天気が崩れたときの判断
release-process: 月 1 回だったリリースを週 1 回にするために、手順と体制を変えた経緯
parent-smartphone: 高齢の親にスマートフォンの使い方を教えるときに、伝わりやすかった方法
