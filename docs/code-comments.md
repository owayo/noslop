# コードのコメントと静的な文言を検査する

[README に戻る](../README.md)

## コードのコメント

コードのファイルでは、日本語のコメントと、ソースで確定する文字列・JSX/HTML の表示文言を文章として検査します。変数の値や、実行して連結した結果は推測しません。

```bash
# 直接渡したコードのファイルは、拡張子から言語を決めてコメントと静的な文言を検査する
noslop check src/lib.rs

# ディレクトリをたどるときは、設定の [code] extensions に書いた拡張子のファイルも集める
noslop check src/
```

```toml
# noslop.toml か ~/.config/noslop/config.toml
[code]
extensions = ["rs", "ts", "tsx", "py", "go", "sh"]
# コメントと Python の docstring だけを検査する場合
# static_text = false
```

- **読める言語**: Rust・C・C++・Python・JavaScript・TypeScript・TSX・Go・PHP・Java・Kotlin・Swift・C#・Bash・Ruby・Lua・HTML・CSS・YAML・TOML です。どのバイナリ（Homebrew・Releases・ソースからのビルド）でも、すべての言語を読めます。`[code] extensions` にコードの拡張子でないものを書くと、設定の誤りになります。`noslop init`（`--user` も）で作るひな形の `[code]` には、読める拡張子すべてを言語ごとに並べてあります（コメントにしてあるので、使うものだけを残して行頭の `#` を外します）
- **取り出し方**: tree-sitter でコメントを読むので、文字列の中の `//`、正規表現、ヒアドキュメントをコメントと取り違えません。隣り合う行の同じ種類のコメント（同じ記号・同じ列）は 1 つにまとめ、コードの後ろのコメントは単独で読みます。記号（`//`・`#`・`/*`・行頭の `*` など）を外した本文を段落にし、指摘の位置は元のファイルの行・列で示します。コメントは句点を打たずに 1 行に 1 つのことを書くことが多いので、行の終わりは文の区切りとして読みます。前の行が読点・助詞・開き括弧で終わるときと、次の行が閉じ括弧・読点で始まるときだけ、1 つの文につなぎます
- **ドキュメントのコメント**: `///`・`/** */`・Python の docstring は Markdown として読み、インラインコードやコードブロックは検査しません。Javadoc と C# の XML ドキュメントは、タグを外して読みます
- **検査しないコメント**: 日本語を含まないもの、shebang、ツールへの指示（`eslint-disable`・`noqa` など）、著作権・ライセンスの表記
- **当てるルール**: コメントと静的な文言は互いに独立した短い断片なので、1 文ずつ判定するルール（語句ルール・独自ルール・R03・R04）だけを当てます。文書・段落をまたいで数えるルール（R01 など）と構造のルール（S）は当てません。ルールはひと続きの文章で校正したもので、コードから取り出した文言での誤検知率は確かめていません
- **抑制**: コメントの中身全体を `noslop-disable-next-line P01 -- 理由` の形（`<!-- -->` で囲んでもかまいません）にすると、抑制コメントとして読みます。文の途中に書いた記法は抑制になりません
- **出力**: JSON の `format` は `"code"` になります。`--stdin-filename` と MCP の `check` の `filename` でも、拡張子から言語を決めます

```rust
// noslop-disable-next-line P01 -- 利用者に見せる案内の定型文のため
/// まとめると、ユーザーの設定にプロジェクトの設定を重ねたものを返します。
```

## 静的な文字列と表示文言

`[code] static_text` は既定で `true` です。`false` にすると、従来のコメントと Python の docstring だけを読みます。この項目もユーザーとプロジェクトの設定を重ね、書いた側の値を使います。CLI・`diff`・フック・MCP で同じ設定が働きます。

通常の文字列、raw 文字列、複数行文字列、補間文字列の静的な区間を読みます。引用符を外し、その言語の形式で決まるエスケープを復号してから日本語の有無を確かめます。補間の前後は別の断片にし、式の中に書かれた文字列も独立して一度だけ読みます。別々の文字列、ボタン名、属性はつなぎません。複数の段落を含む文字列も断片として扱い、文書全体の統計ルールは当てません。

JSX/TSX/HTML の本文では、`span`・`strong`・`em`・`a` などのインライン要素をまたぐ文言をつなぎ、`p`・`div`・見出し・リスト項目・表のセル・`button` などを分けます。`br` は文の区切りです。JSX の式、未知のコンポーネント、除外する部分がある場所でも断片を区切ります。HTML の本文では連続する空白を一つに折り畳み、JSX では行の字下げやタグに隣接する改行を外します。HTML の本文と表示属性にある実体参照も復号します。

表示属性は `title`・`placeholder`・`aria-label`・`aria-description`・`alt`・`label` の固定リストです。`class`・`className`・`id`・`href`・`src`・イベント属性などは、属性内の式にある文字列も含めて読みません。`script`・`style`・`code`・`pre`・`template` と `head` のメタデータは本文の対象外です（`title` 要素は独立して読みます）。HTML の `hidden`、JSX の `hidden` と `hidden={true}` が付いた要素は除外します。`aria-hidden=true` は視覚的な非表示ではないので、それだけでは除外しません。CSS や動的な `hidden` の実行結果は推測しません。

CSS では `content` プロパティの文字列だけ、YAML/TOML では文字列の値だけを読みます。YAML/TOML のキー、JavaScript/TypeScript の構文上明確なプロパティキー、バイト列、正規表現、URL だけの値は除外します。URL を含む文章は残し、変数名や短さから表示用途を推測して外すことはしません。文字列の中に書かれた抑制ディレクティブは読みません。

指摘の位置は元ファイルの行・列です。復号した文字は、そのエスケープまたは実体参照全体の範囲を指します。インラインタグをまたぐ語句の範囲には、間のタグも含まれます。`--git-diff` とフックでは、この元の範囲と文脈で変更行との重なりを判定するため、文言に挟まれたタグの変更でも、その文言の指摘が出ることがあります。不明なエスケープは、前後をつないで新しい語句にしません。C/C++ の狭い文字列にある非 ASCII の数値バイトは文字の符号化を推測せず、その箇所で断片を切ります。Go の数値バイトは連続する区間を UTF-8 として復号し、不正な区間では断片を切ります。
